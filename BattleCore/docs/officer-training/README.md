# Эксперимент с офицером группы

Штатный офицер управляется детерминированным FSM. Включаемый вручную оценщик сравнивает три назначения для второго полка атакующей группы из двух живых полков: поддержка ведущего, атака другого наблюдаемого противника и фланговый обход. Полномочия приказа, состояние полка, проверка проходимости и выбор цели ограничивают набор вариантов. При неверном ответе оценщика или равенстве оценок используется выбор FSM.

Вход сети содержит 28 признаков из `LocalSituation`, донесений своих полков и уже проверенных вариантов: силы и потери, дистанции, относительное положение, прежний приказ, контакт ведущего, обстрел и маску доступных действий. Координаты скрытых противников и результаты боя в признаки сети не входят. Штатные навигация и проверка столкновений используют физическое состояние симуляции для отбраковки маршрутов. Набор приказов формируется до оценки сети.

## Обучение и проверка

- Релизная сборка BattleCore, Clang 19.1.6. Один поток на симуляцию, параллелизм между независимыми боями.
- Сбор данных: 960 исходных боёв, четыре семейства геометрии, 240 зерен на семейство. Размер, вооружение и начальные позиции варьируются по зерну. 20% зерен внутри каждого семейства отводятся под валидацию.
- В 1 247 состояниях сохранено 3 026 исходов для доступных действий. Из одного снимка проигрываются 150 тиков. Для альтернативного действия при повторных допустимых решениях оно получает приоритет в первые 48 тиков. Контрольная ветвь следует обычному FSM. Метки отражают фактические изменения в симуляции.
- Сеть ReLU 28 → 24 → 1, 721 параметр. PyTorch 2.10.0+cu128 обучил её на RTX 3070, 8 ГБ. Целевая величина — разница полезности относительно контрольной ветви. Веса выбраны по MSE на 598 валидационных строках, порог смены приказа — по полезности на той же выборке. Итоговая ошибка на валидации 0,00804.
- Тест: по 100 одинаковых стартов для обеих политик на трёх ранее не использованных семействах. Горизонт — 300 тиков. У каждого прогона записан хеш конечного состояния. Хеши FSM с записью признаков и без неё совпали во всех 300 случаях.
- 24 исходных боя отдельно собраны с одним и шестью рабочими потоками. CSV совпали побайтово. Повторное обучение на том же GPU дало тот же файл весов.

Полезность складывает долю потерь основной цели, долю общих потерь противника, состояние основной цели и прогресс к исходной точке задачи. Из суммы вычитаются доля своих потерь и штраф за переиздание назначения второго полка. Основная цель считается устранённой при уничтожении или панике полка. Подход означает присутствие боеспособного своего полка в радиусе 6 м от исходной точки. Сохранение сил означает потери не выше 25%.

## Воспроизведение

Из каталога BattleCore с настроенным CMake и установленным PyTorch:

```powershell
cmake --build out/build/release --target battle_officer_training
./out/build/release/battle_officer_training.exe collect out/officer-training 240 12
python tools/train_officer.py fit out/officer-training --device cuda --epochs 500
./out/build/release/battle_officer_training.exe evaluate out/officer-training 100 10 out/officer-training/group-policy-v2.txt
python tools/train_officer.py summarize out/officer-training
```

Для обучения на процессоре выберите `--device cpu`. Версия PyTorch для показанного запуска устанавливается командой `python -m pip install torch==2.10.0 --index-url https://download.pytorch.org/whl/cu128`.

`rollouts.csv` содержит локальные признаки, варианты, исполненное действие и исход каждой ветви. `evaluation-decisions.csv` содержит локальные признаки, доступные варианты и выбранный приказ в тестовых боях. `evaluation.csv` связывает их по семейству, зерну и политике с итогами боя. Модель, журнал обучения, сводка и парные итоги приложены к этому отчёту. SHA-256 исходных CSV и весов записаны в JSON.

Нативное включение выполняется через `battle::command::LoadGroupPolicy(std::istream&)` и `battle::SimulationOptions::group_policy`. Объект политики должен жить до завершения вызова `Step`. В рантайме достаточно файла весов и BattleCore. Для продолжения эксперимента со снимка передайте тот же файл модели. Сведения о файле и конфигурации хранятся рядом с результатами эксперимента.
