Goal: remove expensive synchronized ranged steps while retaining individual soldiers, recorded player input, individual projectiles/damage, panic and deterministic save/replay. Work in the user-selected D:/September 4 copy, existing codex/battle-core branch; preserve dirty Unity assets. C++20, existing CMake/Clang toolchain; no added dependencies, no actual UE integration or rendering claims.

Approaches considered: (1) exact nearest-enemy/index optimizations alone preserve targeting and simultaneous release; (2) those optimizations plus deterministic AI firing cohorts distribute release/acquisition work; (3) aggregate regiment damage or new worker pool changes considerably more than needed. Choose (2) under the user's broad ranged authorization. Retain the serial implementation; profile before optimizing unrelated queues.

Proposed mechanics: Rules.ranged_cohorts defaults to4 (validated1..64). Each AI archer has a stable hashed phase from UnitId+RegimentId; idle acquisition attempts run in its phase. First acquisition waits at most3 ticks/150ms. A successful shot's exact ready_tick is also eligible, preserving arbitrary weapon cooldowns during sustained combat; once a due attempt has no target, retry on the next phase. PlayerControlled archers bypass cohorts. With ranged_cohorts=1 every ready archer is eligible each tick, retaining synchronized release. Keep nearest enemy, smaller UnitId on equal float distance, range checks, accuracy formula and projectile travel/resolution/death rules. Do not cache a stale target or turn individual hits into regiment damage.

Targeting: extend UnitPosition with team and payload_index (index valid only for the current immutable combat read). Add FindNearestEnemy returning stable ID+payload index. Search near cells first with conservative pruning and a finite large-query fallback; skip friendly candidates before detailed distance. Do not collect/sort/deduplicate a radius-result vector for every attacker. Build one team/index record per live unit, access a chosen target once by payload index. Retain public radius APIs for other clients. If no eligible attacker exists, skip the spatial rebuild. Differential tests compare nearest selection to the existing full-radius/float-distance rule, including ties, boundaries, Z, negative coordinates, sparse IDs, input reversal and large radii.

Measurement: optional non-authoritative StepProfile separates command/AI, movement, targeting and commit time; enabling it cannot change StateHash or persistent state. Benchmark writes stage percentiles and raw samples. Baseline and final volley:1k/5k/10k/20k, seed42,200 warmup+1200 measured ticks,3 independent runs; final also compare cohort1 and cohort4 at10k. Measure melee regression at10k and20k. Target:10k volley p99<50ms, aim<=20ms; report actual and max, no claimed speedup before measurement. Timing includes all individual combat work and excludes rendering/I/O as before. Profile commit before considering a due-queue rewrite; leave it intact if not material.

Persistence: add ranged_cohorts to scenario JSON defaults, state hashing and validation. New snapshots/replay records use schema_version2; reject v1 explicitly rather than silently changing continuation mechanics. Scenario authoring schema remains1 with the new default. Existing reports/artifacts identify the previous build. New saves include the rule and need no per-unit scheduler state; phase is derived from persistent IDs and ready_tick.
